# TOUKOU（逃講）仕様書

> **授業はスキップしても、学びはスキップしない。**

この文書が TOUKOU の仕様の正本です。仕様を変えるときは、この文書を更新する PR を出してください。
「仮決め」と書いた項目は、担当者が決めて変えてかまいません。変えたらこの文書も更新します。

## 1. どんなアプリか

大学生向けの AI 学習・時間管理アプリです。

- 授業に出られない日も、講義の内容を追いやすくする
- 授業に出る日も、理解と時間の使い方を助ける
- ブランドは少し反抗的でユーモラス。ただし UI と機能はシンプルで実用的にする
- **出席の代わりになるものではありません**（出席要件をごまかす機能は作らない）

## 2. コア機能（4 つ）

| #   | 機能                   | 内容                                                                                                                       |
| --- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | 次の授業案内・予習復習 | 時間割から、次の授業の科目・開始時刻・建物・階数・教室を表示する。講義資料から前回のまとめと短い確認問題を出す             |
| 2   | 板書の知識拡張カメラ   | 板書の写真を読み取り、数式・用語・省略された説明を解説する                                                                 |
| 3   | 空きコマ提案           | 次の授業までの時間、課題の締切、復習候補、移動時間から、勉強や休憩を含む過ごし方を提案する。教室への移動時間は必ず確保する |
| 4   | 問題共有               | 板書や資料から AI が問題と解説を作り、URL で友達に送る。受け取った人はアプリに登録しなくても回答できる                     |

### 一番大事な設計の考え方

**同じ講義資料・板書を 4 つの機能で使い回す。**
1 枚の板書を登録したら、それが「解説（機能 2）」「復習（機能 1）」「空きコマの復習候補（機能 3）」「共有する問題（機能 4）」に全部つながる。
機能をばらばらに作って寄せ集めにしないでください。データは `materials`（資料）を中心につなげます（6 章）。

## 3. MVP（最初に作るもの）

- 科目・曜日・時限・建物・階数・教室を手で登録し、時間割を表示する
- ホームに「次の授業の科目／開始時刻／建物／階数／教室」と、開始までの残り時間を表示する
- 移動時間は、ユーザーが設定する「移動の余裕時間（分）」で扱い、「何時何分に移動を始めればよいか」を表示する（屋内の経路検索はしない）
- 科目に講義資料や板書の画像を追加する
- 画像・資料から、AI で要約／解説／確認問題を作る
- 次の授業と空き時間に合わせた提案をホームに表示する
- 作った問題を URL で共有し、受け取った人が回答して解説を見られる

### 後回し（MVP では作らない）

プッシュ通知、板書画像のタップ位置の正確な解析、学内システムとの連携、屋内経路案内、高度な学習分析、ランキング。

### 機能を増やしすぎない

MVP に無い機能を思いついたら、実装する前に issue に書いてチームで相談してください。

## 4. 画面

| 画面           | パス（仮決め）                  | 内容                                                                                 |
| -------------- | ------------------------------- | ------------------------------------------------------------------------------------ |
| ホーム         | `/`                             | 次の授業（時刻・建物・階数・教室）、移動開始の目安、短い復習、空きコマ提案           |
| 時間割         | `/timetable`                    | 科目・曜日・時限・建物・階数・教室の登録と表示。時限ごとの時刻、移動の余裕時間の設定 |
| 資料／カメラ   | `/materials`、`/materials/[id]` | アップロード、AI の解説、科目別の履歴                                                |
| 問題共有       | `/questions`                    | 問題の作成、確認、共有 URL の発行                                                    |
| 共有された問題 | `/q/[shareId]`                  | ログイン不要。回答して解説を見る                                                     |
| ログイン       | `/login`                        | Supabase Auth を使う                                                                 |

## 5. 最初に通したい一連の流れ（デモのシナリオ）

1. 時間割に科目と教室を登録する
2. ホームに次の授業の場所と、移動開始の目安が表示される
3. 板書を 1 枚アップロードする
4. AI が解説と確認問題を作る
5. 空きコマの提案に、その板書の復習が候補として出る
6. 確認問題を友達に URL で共有し、友達がログインせずに回答できる

この流れが最後まで通ることが、MVP の完成条件です。

## 6. データ（仮決め。DB+security 担当が migration で確定する）

```
profiles        ユーザーごとの設定（移動の余裕時間、時限ごとの開始・終了時刻）
courses         科目（user_id, 名前, 曜日, 時限, 建物, 階数, 教室）
materials       講義資料・板書（user_id, course_id, 種類, Storage のパス, 作成日時）
material_notes  AI が作った要約・解説（material_id, 種類, 本文）
questions       確認問題（user_id, material_id, 問題文, 選択肢, 正解, 解説, 公開フラグ, share_id）
answers         共有された問題への回答（question_id, 回答, 正誤, 作成日時）
```

- 時限の時刻は大学によって違うので、`profiles` にユーザーが設定する（初期値は 1 限 9:00 から 90 分 + 休み 10 分などで仮決め）
- 空きコマ提案はまず計算（ルール）で作り、文面だけ AI に任せてもよい（仮決め）

## 7. 守ること（プライバシーと AI）

- **板書・講義資料は非公開が基本。** 本人以外は見られないようにする（Supabase の RLS と非公開の Storage）
- **問題を共有するときは、本人が確認して「公開」を押した問題文と解説だけを公開する。** 元の板書画像は公開しない
- **AI の出力は間違うことがある。** AI の解説や問題には、元の資料（画像）を開けるリンクを必ず付ける
- 共有ページ `/q/[shareId]` は推測されにくい ID を使う（連番にしない）

## 8. 技術構成

| 項目               | 使うもの                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| フレームワーク     | Next.js（App Router、TypeScript）                                                                |
| スタイル           | Tailwind CSS                                                                                     |
| DB・認証・画像保存 | Supabase（Postgres、Auth、Storage）                                                              |
| AI                 | Vercel AI SDK（`ai`）。OpenAI か Google Gemini を環境変数で切り替える。`mock` でキー無しでも動く |
| 入出力の型         | zod（`src/contracts/`）                                                                          |
| デプロイ           | Vercel（仮決め。まだ設定していない）                                                             |

フォルダ構成と役割分担は [architecture.md](architecture.md) を見てください。
