# 用語集

分からない言葉があったら、ここを見るか AI エージェントに聞いてください。

## Git・GitHub

| 用語                     | 意味                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| リポジトリ（repo）       | プロジェクトのファイルと変更履歴をまとめたもの。TOUKOU の場合は https://github.com/KukimiCan/TOUKOU |
| clone                    | GitHub のリポジトリを自分のパソコンにコピーすること                                                 |
| commit                   | 変更を「ひとまとまりの記録」として保存すること。ゲームのセーブのようなもの                          |
| ブランチ（branch）       | 作業用の分かれ道。自分のブランチで作業すれば、main を壊さない                                       |
| main                     | 完成品が置かれる本線のブランチ。直接変更しない                                                      |
| push                     | 自分のパソコンの commit を GitHub に送ること                                                        |
| pull                     | GitHub の最新の変更を自分のパソコンに取り込むこと                                                   |
| issue                    | やること・バグ・相談を書くチケット。1 つの作業に 1 つ                                               |
| PR（Pull Request）       | 「自分のブランチの変更を main に入れてください」というお願い。CI が通ったら merge する              |
| merge                    | ブランチの変更を別のブランチ（main など）に合流させること                                           |
| コンフリクト（conflict） | 2 人が同じファイルの同じ場所を変えて、Git がどちらを残すか決められない状態                          |
| レビュー                 | 他の人の変更を見て、問題が無いか確かめること                                                        |
| CI                       | PR を出すと GitHub が自動で動かすチェック（lint、型チェック、ビルド）                               |
| sub-issue                | 親 issue を小さく分けた issue。作業は sub-issue 単位で行う                                          |
| ラベル                   | issue や PR に付ける目印。`role:front` など                                                         |

## 開発

| 用語                     | 意味                                                                              |
| ------------------------ | --------------------------------------------------------------------------------- |
| ターミナル               | 文字で命令してパソコンを動かす画面                                                |
| Node.js                  | JavaScript をパソコン上で動かすための土台                                         |
| npm                      | Node.js のライブラリを入れたり、`npm run dev` などのコマンドを動かす道具          |
| ライブラリ（パッケージ） | 他の人が作った便利な部品。`package.json` に一覧がある                             |
| TypeScript               | 型（データの形）を書ける JavaScript。間違いに早く気づける                         |
| 型                       | 「このデータは文字列」「この中に name がある」などのデータの形の約束              |
| lint                     | コードの書き方の問題を自動で見つけるチェック（`npm run lint`）                    |
| ビルド                   | アプリを公開できる形に変換すること（`npm run build`）                             |
| 環境変数                 | パスワードや API キーなど、コードに直接書かない設定。`.env.local` に書く          |
| localhost                | 自分のパソコンのこと。`http://localhost:3000` は自分のパソコンで動いている TOUKOU |

## TOUKOU の技術

| 用語                      | 意味                                                                                   |
| ------------------------- | -------------------------------------------------------------------------------------- |
| Next.js                   | TOUKOU の画面と API を作るフレームワーク。`src/app` のフォルダ名がそのまま URL になる  |
| React                     | 画面を部品（コンポーネント）の組み合わせで作る仕組み。Next.js の中で使う               |
| コンポーネント            | 画面の部品。ボタン、カード、一覧など                                                   |
| Tailwind CSS              | `className="text-lg"` のようにクラス名で見た目を決める仕組み                           |
| API                       | 画面からサーバーに「データをちょうだい」「保存して」と頼む窓口。TOUKOU では `/api/...` |
| Route Handler             | Next.js で API を作る仕組み。`src/app/api/<名前>/route.ts`                             |
| Supabase                  | DB、ログイン、画像の保存をまとめて提供するサービス                                     |
| DB（データベース）        | データを表（テーブル）の形で保存する場所                                               |
| テーブル                  | DB の中の表。`courses`（科目）など                                                     |
| migration                 | テーブルの作成や変更を SQL ファイルとして記録したもの                                  |
| SQL                       | DB に命令するための言葉                                                                |
| RLS（Row Level Security） | 「この行はこの人だけが見られる」という DB のルール。他人のデータを守る                 |
| Storage                   | Supabase の画像やファイルの置き場所                                                    |
| zod                       | データの形をチェックするライブラリ。`src/contracts/` で使う                            |
| contracts                 | front と back の「API はこの形でやりとりする」という約束（`src/contracts/`）           |
| mock                      | 本物の代わりの仮のもの。仮データ、仮の AI の結果など                                   |
| AI SDK                    | OpenAI や Gemini を同じ書き方で呼べるライブラリ（`ai`）                                |
| プロンプト                | AI への指示文                                                                          |
