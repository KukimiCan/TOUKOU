# はじめての AI 担当ガイド（Antigravity + 無料の Gemini）

プログラミングも GitHub も初めての人が、**AI 担当**として TOUKOU の開発に参加するためのガイドです。
使う道具は、無料で使える **Antigravity**（Google の AI エージェント付き開発アプリ）と **Gemini** です。

- 上から順番に、1 ステップずつ進めてください。飛ばさないでください
- 各ステップの最後に「✅ できたら」があります。そこまで確認できたら次に進みます
- 分からなくなったら、[最後の章](#12-困ったとき) を見てください。それでもだめならチームに聞いてください。初心者が質問するのは当然です

> コードを自分で書けなくても大丈夫です。コードを書くのは Antigravity のエージェントです。
> あなたの仕事は、**何を作るかを伝える → エージェントの計画を確かめる → 結果が正しいか確かめる** ことです。

---

## 0. 全体の地図

### TOUKOU の中で AI 担当がやること

TOUKOU は、板書の写真を AI が解説したり、確認問題を作ったりするアプリです（[仕様書](../spec.md)）。
AI 担当は、**「板書の画像を渡すと、解説や問題が返ってくる関数」** を作ります。画面（front）や保存（back、DB）は他の人の担当です。

### 使う道具

| 道具               | 何に使うか                                          | 費用                                   |
| ------------------ | --------------------------------------------------- | -------------------------------------- |
| GitHub（ブラウザ） | やること（issue）の確認、作ったものの提出（PR）     | 無料                                   |
| Git                | 変更の記録。Antigravity のエージェントが操作する    | 無料                                   |
| Node.js            | TOUKOU を自分のパソコンで動かす土台                 | 無料                                   |
| Antigravity        | AI エージェントにコードを書いてもらうアプリ         | 無料プランあり（週ごとの利用上限あり） |
| Google AI Studio   | TOUKOU から Gemini を呼ぶための **API キー** を作る | 無料枠あり                             |

### 進め方の全体像

```
1〜5. 準備（アカウント、インストール、TOUKOU を動かす）     ← 1 日目
6.    Gemini の API キーを作る
7.    Antigravity の使い方を覚える
8.    最初の issue（#17：使う AI を決める）※コードを書かない
9.    最初のコードの issue（#76）を、提出まで一通りやる
10.   残りの AI の issue を順番に進める
```

## 5. TOUKOU を Antigravity で開いて、動かす

### 5-1. フォルダを開く

Antigravity で、デスクトップの `TOUKOU` フォルダを開きます（新しいプロジェクト／フォルダを追加、のような操作）。
作業のモードを聞かれたら **Local mode**（今のフォルダで作業する）を選びます。

> TOUKOU には `AGENTS.md` という「エージェントへのルール」が入っています。Antigravity はこれを自動で読みます。

### 5-2. エージェントに起動してもらう

ここから、エージェントに頼んでみます。エージェントとの会話の欄に、次の文章を貼って送ってください。

```
私はプログラミング初心者で、TOUKOU の AI 担当です。
docs/getting-started.md の 5〜7 を一緒に進めたいです。
1. npm install を実行してください
2. .env.example をコピーして .env.local を作ってください（中身は変えないで）
3. npm run dev で起動して、http://localhost:3000 を開けるようにしてください

```

エージェントがコマンドを実行しようとすると、**許可を求められる**ことがあります。説明を読んで、問題なさそうなら許可します（[7 章](#7-antigravity-の使い方の基本)）。

### 5-3. ブラウザで確認する

ブラウザで http://localhost:3000 を開きます。

✅ できたら：「開発環境の状態」が表示され、`AI（mock）: OK` と出ている。
これで **issue #1（環境構築）** は完了です。https://github.com/KukimiCan/TOUKOU/issues/1 を開き、下のコメント欄に「完了」と書いて **Comment** を押してください。

> 止めるときは、`npm run dev` を実行しているターミナルで `Ctrl + C` を押します。エージェントに「開発サーバーを止めて」と頼んでもかまいません。

## 6. Gemini の API キーを作る

TOUKOU のプログラムから Gemini を呼ぶには、**API キー**（合言葉のような長い文字列）が必要です。

1. https://aistudio.google.com/ を開き、Google アカウントでログインする
2. 画面の **Get API key**（API キーを取得）から、キーを作る
3. 表示されたキーをコピーする
4. Antigravity で `.env.local` を開き、次のように書き換えて保存する

```
AI_PROVIDER=google
AI_MODEL=（#17 で決めたモデル名。まだなら空のまま）
GOOGLE_GENERATIVE_AI_API_KEY=（コピーしたキー）
```

### ⚠️ API キーと無料枠の注意（必ず読む）

- **API キーは他人に見せない。** GitHub、issue、PR、チャット、スクリーンショットに貼らない。`.env.local` は GitHub に送られない設定になっているので、ここにだけ書く
- もしキーを公開してしまったら、すぐに AI Studio でそのキーを削除して作り直し、チームに伝える
- **無料枠では、送った内容（文章や画像）と AI の返事が、Google のサービス改善に使われ、人が読むこともあります**（[Gemini API の利用規約](https://ai.google.dev/gemini-api/terms)）。規約にも「機密情報や個人情報を送らないこと」と書かれています
  - 試すときは、**名前・顔・学籍番号など個人の情報が写っていない板書**だけを使う
  - 配布禁止の授業資料はアップロードしない
- 無料枠には **1 分あたり・1 日あたりの回数の上限** があります。上限を超えると `429` というエラーになります。少し待つか、`AI_PROVIDER=mock` に戻して作業を続けます

✅ できたら：`.env.local` にキーが入っている（`npm run dev` を再起動すると、`AI（google）: OK` と表示される）

## 7. Antigravity の使い方の基本

画面の見た目はバージョンによって変わります。この文書の説明と違うときは、エージェントに「〇〇はどこ？」と聞いてください。

### エージェントとのやりとりの流れ

```
あなた：やってほしいことを書く
   ↓
エージェント：計画（何をどう変えるか）を出す
   ↓
あなた：計画を読む。分からない言葉は質問する。よければ OK と返す
   ↓
エージェント：ファイルを変更したり、コマンドを実行したりする（許可を求められたら確認する）
   ↓
あなた：結果を確かめる（画面、コマンドの結果、変更されたファイル）
```

### 許可を求められたときの判断

| エージェントがやろうとしていること                                         | どうするか                                                                                       |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `npm run dev`、`npm run check`、`npm install`、`git status`、`git diff`    | 許可してよい                                                                                     |
| `git switch -c ...`（ブランチを作る）、`git add`、`git commit`、`git push` | 許可してよい（9 章の流れの中なら）                                                               |
| `src/lib/ai/` の中のファイルを作る・変える                                 | 許可してよい（AI 担当の持ち場）                                                                  |
| `src/lib/ai/` **以外**のファイルを変える                                   | 一度止めて「なぜそのファイルを変えるの？」と聞く。他の役割の持ち場なら変えずに、チームに相談する |
| `git reset --hard`、`git push --force`、ファイルやフォルダの削除           | **許可しない。** チームに相談する                                                                |
| `.env.local` の中身を表示する、どこかに送る                                | **許可しない**                                                                                   |

### 無料プランの利用上限

Antigravity の無料プランには、**週ごとの利用上限**があります。上限に近づいたら：

- 1 回の頼みごとを小さくする（「全部作って」より「スキーマだけ作って」）
- 同じ説明を何度もさせない。分かったことはメモしておく
- 上限に達したら、リセットされるまで、ブラウザの Gemini（https://gemini.google.com/ ）で質問したり、GitHub で他の人の PR を見たりする

## 8. 最初の issue：#17「使う AI とモデルを決める」

最初は、コードを書かない issue から始めます。

### 8-1. 担当になる

1. https://github.com/KukimiCan/TOUKOU/issues/17 を開く
2. 右側の **Assignees** を押し、自分を選ぶ（「私がやります」の印）

### 8-2. 調べる

Antigravity のエージェント（またはブラウザの Gemini）に、次のように聞きます。

```
TOUKOU は板書の写真を AI に解説させるアプリです。
Gemini API の無料枠で使えるモデルのうち、画像を入力できて、
解説や問題作りに向いているものを、候補を 2〜3 個挙げて比べてください。
無料枠の回数制限も教えてください。
最新の情報は Google AI Studio と https://ai.google.dev/ で確かめるので、確認すべきページも教えてください。
```

> AI の答えは古かったり間違っていたりします。モデル名と制限は、**Google AI Studio の画面や公式ページで自分の目で確かめて**ください。

### 8-3. 試す

Google AI Studio の画面で、候補のモデルを選び、**個人情報が写っていない**板書の写真を貼って「この板書を大学生向けに解説して」と頼みます。結果を比べてください。

### 8-4. 決めてコメントする

issue #17 のコメント欄に、次の形で書いて **Comment** を押します。

```
使う AI：Gemini（AI_PROVIDER=google）
モデル：〇〇〇
理由：画像を入力できる、無料枠で 1 日〇回使える、試した結果がわかりやすかった
注意：無料枠なので、個人情報が写った画像は送らない
```

**API キーはコメントに書かないでください。** キーは各自が AI Studio で作ります。

チームに「#17 で決めました」と伝え、全員に `.env.local` の `AI_PROVIDER` と `AI_MODEL` をそろえてもらいます。最後に、右下の **Close issue** を押して閉じます。

✅ できたら：#17 が閉じていて、チームにモデル名が伝わっている

## 9. 最初のコードの issue：#76「板書解説の出力スキーマと mock」

ここで、**issue を選んでから提出するまで**を一通りやります。一度できれば、残りの issue も同じ流れです。

> **スキーマ**とは「AI の答えの形」の約束です。例えば「要約（文章）と、用語の一覧（用語と意味）を返す」のように決めます。
> **mock** とは「本物の AI を呼ばずに返す仮の答え」です。キーが無い人や、他の担当の人が困らないように作ります。

### 9-1. 担当になる

https://github.com/KukimiCan/TOUKOU/issues/76 を開き、**Assignees** で自分を選びます。本文の「完了条件」を読んでおきます。

### 9-2. 作業用のブランチを作る

**ブランチ**は、みんなの完成品（`main`）を壊さずに作業するための、自分専用のコピーです。エージェントに頼みます。

```
issue #76 を始めます。
main を最新にしてから、ai/76-explanation-schema という名前のブランチを作って、そこに切り替えてください。
```

✅ できたら：エージェントが `git switch -c ai/76-explanation-schema` のようなコマンドを実行し、成功している

### 9-3. エージェントに作ってもらう

```
私は TOUKOU の AI 担当で、プログラミング初心者です。issue #76 をやります。
https://github.com/KukimiCan/TOUKOU/issues/76
AGENTS.md と docs/roles/ai.md を読んでください。
板書の解説（要約、用語と意味、数式の説明、省略された説明）の zod スキーマを src/lib/ai/ に、
mock の結果を src/lib/ai/mocks/ に作りたいです。
まず、どんなファイルを作り、どんな形にするかを、初心者にも分かるように説明してください。
私が OK と言うまで、ファイルは作らないでください。
```

エージェントの説明を読んで、分からない言葉があれば聞きます。

```
「zod スキーマ」と「型」の違いを、たとえ話で説明して
```

よければ「OK、作ってください」と返します。

### 9-4. 確かめる

```
npm run format と npm run check を実行して、エラーがあれば直してください。
最後に、変更したファイルの一覧と、それぞれ何をしたかを教えてください。
```

自分でも確かめます。

- 変更されたファイルが `src/lib/ai/` の中だけか
- mock の中身が、日本語として自然な「板書の解説っぽい」内容か
- issue #76 の完了条件を満たしているか

### 9-5. 記録して GitHub に送る（commit と push）

**commit** は変更の記録（セーブ）、**push** は GitHub に送ることです。

```
git status で変更を確認してから、変更を commit してください。
メッセージは「feat: 板書解説のスキーマと mock を追加 (#76)」にしてください。
.env.local が含まれていないことを必ず確認してください。
その後、git push -u origin HEAD で GitHub に送ってください。
```

### 9-6. 提出する（PR を作る）

**PR（プルリクエスト）** は「この変更を main に入れてください」というお願いです。

```
gh pr create --web を実行して、ブラウザで PR を作れるようにしてください。
```

ブラウザが開いたら、テンプレートに沿って書きます。

- 「関連 issue」の `Closes #` の後ろに `76` を書く → `Closes #76`
- 「やったこと」に、作ったものを 1〜2 行で書く
- 「確認方法」に、自分が確かめたことを書く

**Create pull request** を押します。

### 9-7. CI を待って merge する

PR を作ると、GitHub が自動でチェック（**CI**）をします。数分待つと、PR の画面の下のほうに結果が出ます。

- ✅（緑）：OK。**Squash and merge** → **Confirm** を押す。その後 **Delete branch** を押す
- ❌（赤）：**Details** を押してエラーを見る。エラーの文章をエージェントに貼り、「CI でこのエラーが出た。直して commit と push して」と頼む。直ると PR が自動で更新される

✅ できたら：PR が紫色の **Merged** になり、issue #76 が自動で閉じている

### 9-8. main に戻る

```
main に切り替えて、最新の状態にしてください（git switch main と git pull）。
```

🎉 これで一通りできました。チームに「#76 終わりました」と伝えましょう。

## 10. 残りの AI の issue

上から順番に進めると、前の issue の成果を次で使えます。どれも 9 章と同じ流れです（担当になる → ブランチ → 作ってもらう → 確かめる → commit・push → PR → merge）。

| 順番 | issue | 内容                                       | ブランチ名の例             |
| ---- | ----- | ------------------------------------------ | -------------------------- |
| 1    | #17   | 使う AI とモデルを決める（コードなし）     | なし                       |
| 2    | #76   | 板書解説の出力スキーマと mock              | `ai/76-explanation-schema` |
| 3    | #77   | 板書解説のプロンプトと関数                 | `ai/77-explain-board`      |
| 4    | #78   | 板書解説を実際の板書で試す                 | `ai/78-try-explanation`    |
| 5    | #79   | 確認問題の出力スキーマと mock              | `ai/79-question-schema`    |
| 6    | #80   | 確認問題のプロンプトと関数                 | `ai/80-generate-questions` |
| 7    | #81   | 確認問題の品質を確かめる                   | `ai/81-question-quality`   |
| 8    | #82   | 空きコマ提案の入出力と mock（back と相談） | `ai/82-suggestion-schema`  |
| 9    | #83   | 空きコマ提案のプロンプトと関数             | `ai/83-suggestion`         |

**プロンプト**（#77、#80、#83）は、AI への指示文です。コードが書けなくても、ここは AI 担当の腕の見せどころです。

- 「大学生向けに」「専門用語には短い説明を付けて」など、誰に向けた答えかを書く
- 「板書に書かれていないことは書かない」「読めない部分は『読み取れません』と書く」など、間違いを防ぐ指示を入れる
- 実際の板書で何回か試して、結果を見ながら直す

## 11. エージェントへの頼み方のコツ

| コツ                       | 例                                            |
| -------------------------- | --------------------------------------------- |
| 自分が初心者だと伝える     | 「初心者なので、専門用語には説明を付けて」    |
| まず計画を出させる         | 「まず計画を説明して。OK するまで作らないで」 |
| 小さく頼む                 | 「関数全部」より「スキーマだけ」              |
| 範囲を決める               | 「`src/lib/ai/` 以外は変えないで」            |
| エラーはそのまま貼る       | 「このエラーが出た。原因と直し方を教えて」    |
| 分からなければ何度でも聞く | 「今のをもっと簡単に説明して」                |
| 最後にまとめさせる         | 「何を変えたか、次に何をすればいいか教えて」  |

エージェントの説明が正しいとは限りません。**画面やコマンドの結果で確かめる**のを忘れないでください。

## 12. 困ったとき

| 症状                                      | どうするか                                                                                                                      |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 何が起きているか分からない                | エージェントに「`git status` を実行して、今どういう状態か初心者向けに説明して」と頼む                                           |
| 間違えて main で作業してしまった          | エージェントに「main で作業してしまった。変更を消さずに ai/◯◯ というブランチに移して」と頼む                                    |
| 変更を全部やめて最初からやり直したい      | **自分で消さずに**チームに相談する                                                                                              |
| エージェントが他の担当のファイルを変えた  | 「そのファイルの変更を元に戻して」と頼む。必要な変更なら、その担当者にお願いする issue を作る                                   |
| `429` / `RESOURCE_EXHAUSTED` というエラー | Gemini の無料枠の上限。少し待つか、`.env.local` を `AI_PROVIDER=mock` にして作業を続ける                                        |
| `API key not valid` というエラー          | `.env.local` のキーが間違っている。余計な空白や `"` が無いか確かめ、`npm run dev` を再起動する                                  |
| Antigravity の上限に達した                | リセットまで、ブラウザの Gemini で質問する、他の人の PR を見る、など                                                            |
| PR に「This branch has conflicts」と出た  | エージェントに「main の変更を取り込んで、コンフリクトを解決して」と頼む。`src/lib/ai/` 以外でコンフリクトしたらチームに相談する |

### チームに質問するときに書くこと

1. 今やっている issue の番号
2. やろうとしたこと
3. 起きたこと（エラーの文章をそのままコピー。**API キーが含まれていないか確認してから**貼る）
4. 自分で試したこと
